# Заняття 3. Перший API-виклик: функція `llm()` на двох провайдерах

Один контракт — кілька провайдерів. Усе, що залежить від провайдера, живе
всередині `llm()`; код прогону тестсету про провайдерів не знає нічого.

## Файли

| файл | що це |
|---|---|
| `llm.py` | функція `llm()`: google / openai / anthropic, retry, токени, вартість |
| `testset.py` | промпт v2 (6 блоків) + 5 входів + автоматичний валідатор відповіді |
| `run_testset.py` | Кроки 5–6: 10 викликів, таблиця в `results.md` + сирі дані в `results.json` |
| `retry_demo.py` | Крок 4: доказ, що retry працює (3 сценарії) |
| `mock_run.py` | прогін конвеєра без ключів і без мережі — перевірити код, поки ключів немає |

## Політика retry

`1 → 2 → 4 → 8` секунд, максимум 5 спроб, після останньої — `LLMError`, ніяких `None`.

Повторюємо тільки те, що має шанс полагодитись саме собою: `429`, `5xx`, таймаути,
обриви зʼєднання. `400/401/403` не повторюємо — невірний ключ не стане вірним
із пʼятої спроби, а чекання 15 секунд лише ховає помилку.

`429` буває двох протилежних сортів, і плутати їх дорого: «занадто часто» мине саме,
«немає грошей» (`insufficient_quota`, `credit balance is too low`) не мине ніколи.
Другий не ретраїмо. Маркери мають бути вузькі: Google у своєму 429 про частоту теж
згадує billing, і надто широкий маркер ховав цілком відновлювану помилку.

Якщо сервер сам каже, скільки чекати (`Please retry in 23.9s`), беремо більшу з двох
затримок — сліпий backoff 1-2-4-8 такого вікна не перечекає в принципі.

Для скріншота в ДЗ потрібно побачити всі 5 спроб саме на невірному ключі, тому
`retry_demo.py badkey` вмикає `LLM_RETRY_ALL_ERRORS=1` — це прапорець для демо,
а не робоча поведінка. Три сценарії:

```bash
python retry_demo.py                  # імітований 429, офлайн, без ключів
python retry_demo.py badkey google    # реальний невірний ключ, 5 спроб, 1→2→4→8 c
python retry_demo.py fatal google     # той самий ключ, штатна політика: падаємо одразу
```

## Вартість

`cost = (in_tokens * price_in + out_tokens * price_out) / 1_000_000`

Ціни лежать у `PRICES` в `llm.py`, посилання на офіційні прайси — у `PRICING_SOURCES`
і в `results.md`. **Звір ціни перед здачею**: вони змінюються, і числа в репозиторії
можуть застаріти.

## Граблі, на які вже наступили

- **Змінив `.env` — перезапусти процес.** `load_dotenv()` читає файл один раз на старті.
- **Моделі зникають.** `gemini-2.5-flash` новим ключам уже не видають — 404 із
  підказкою оновитися. Не вір списку моделей у чужому коді, спитай API:
  `client.models.list()`.
- **Gemini «думає» за замовчуванням.** Токени міркувань їдять `max_output_tokens`,
  і замість JSON приходить порожній рядок із `finish_reason=MAX_TOKENS`. Рятує
  `thinking_config=ThinkingConfig(thinking_budget=0)` — але його приймають не всі
  моделі: 3.7 і 3.8 так, 3.6 і 3.5-flash-lite віддають 400.
- **Квота безкоштовного тарифу Google — на кожну модель окремо** (20 запитів).
  Уперся в ліміт на одній моделі — сусідня ще працює.
- **Моделі з міркуваннями пишуть роздуми у вихідні токени.** `gpt-oss-120b` на
  одному кейсі витратив 820 токенів там, де JSON важить 150: на `max_tokens=500`
  відповідь обривало і Groq повертав `400 json_validate_failed`. Не «поганий промпт»,
  а замалий ліміт.
- **`temperature` в Anthropic більше не існує** — параметра немає ні в API, ні в
  сигнатурі SDK 1.x, разом із `top_p`/`top_k`. Вимогу «temperature=0» там виконати
  неможливо; гілка приймає аргумент заради єдиного контракту і відкидає його.
- **Корпоративні (identity-linked) ключі Anthropic** вимагають заголовок
  `anthropic-workspace-id`, інакше 400. Підтримка — через `ANTHROPIC_WORKSPACE_ID`.
- **Anthropic:** `max_tokens` обовʼязковий, `system` — окремий параметр, а не елемент
  `messages`. Інакше `400`.
- **Anthropic + `ANTHROPIC_BASE_URL`.** Якщо ця змінна є в оточенні (буває від
  локальних проксі), SDK піде туди, а не в API Anthropic. Перевір: `echo $ANTHROPIC_BASE_URL`.
- **Невірний ключ із кирилицею** впаде `UnicodeEncodeError` ще в HTTP-заголовку —
  побачиш не відповідь сервера, а помилку кодування. Для демо бери ASCII.
- **429 на безкоштовному тарифі.** Між викликами стоїть пауза `LLM_SLEEP_BETWEEN`
  (за замовчуванням 4 c).
- **Обрізана відповідь** — дивись `stop_reason`: `max_tokens`/`length` означає, що
  винен не промпт, а ліміт. Валідатор це підписує окремо.

## Що виміряно
